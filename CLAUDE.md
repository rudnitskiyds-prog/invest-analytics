# ИнвестАналитика — инструкции для Claude

Информационно-аналитическая платформа оценки эффективности инвестиций на российском рынке:
данные ISS Московской биржи и Банка России, коэффициенты эффективности из НИР
«Сравнительный анализ пассивных стратегий управления инвестиционным портфелем на российском
финансовом рынке», граница Марковица, бэктест, учёт портфеля, календарь ребалансировок.

Язык интерфейса, сообщений коммитов и отчётов — русский.

## Структура

| Путь | Что там | Владелец (субагент) |
|---|---|---|
| `core/data/` | клиенты ISS MOEX и ЦБ, кэш, каталог активов | `api` |
| `core/analytics/` | коэффициенты, граница Марковица, бэктест, стратегии НИР, витрина | `api` |
| `core/portfolio/` | учёт портфеля, ребалансировки | `api` |
| `scripts/`, `.github/workflows/`, `public/data/` | сборщик данных ЦБ, сверка с НИР, расписания | `api` |
| `app.py`, `pages/`, `ui/`, `.streamlit/`, `docs/screenshots/` | интерфейс (сейчас Streamlit; будущий статический сайт — `web/`) | `site` |
| `tests/` | pytest, эталонные данные в `tests/fixtures/` | `tests` |

## Команды

```bash
pip install -r requirements.txt -r requirements-dev.txt
pytest -q                          # все тесты, сеть не нужна
python -m scripts.reproduce_nir    # сверка бэктеста с табл. 4 НИР
IP_OFFLINE=1 streamlit run app.py  # интерфейс на демо-данных
python -m scripts.collect_data     # сбор данных ЦБ в public/data/ (нужна сеть)
```

## Инварианты — нарушать нельзя

1. `pytest -q` проходит полностью. Тесты не ходят в сеть (сетевые вызовы — через monkeypatch / фикстуры).
2. `tests/test_nir_reproduction.py` — эталон методики. Если правка меняет цифры сверки с табл. 4 НИР,
   это не «починка теста», а изменение методики: остановиться и спросить пользователя.
3. Формулы коэффициентов — в `core/analytics/metrics.py` и в странице «Методика»; меняются только вместе.
4. `core/` не импортирует Streamlit. Интерфейс не считает финансы сам — только вызывает `core/`.
5. Данные: ISS и ЦБ — через официальные выгрузки (JSON ISS, XML/SOAP ЦБ), не парсинг HTML.
   Котировки Мосбиржи в репозиторий не коммитим, кроме эталонных фикстур и `public/data/` от сборщика.
6. Секреты и токены не попадают в код и коммиты.
7. Агенты не сливают изменения в `main`. Результат — ветка и Pull Request; слияние делает человек.

## Командный процесс: 3 исполнителя + критик

Для любой задачи, затрагивающей больше одного слоя (новая функция, страница, источник данных),
основной агент работает как координатор и действует строго так:

1. **План.** Разобрать задачу, создать ветку `feature/<кратко>` от свежего `main`
   (`git pull` перед началом: сборщик данных ежедневно коммитит в `main`).
   Разбить работу на задания для `api`, `site`, `tests` с явным контрактом между ними:
   имена функций `core/`, их аргументы и что они возвращают.
2. **Реализация — параллельно.** Запустить субагентов `api` и `site` одновременно, передав каждому
   его задание и контракт. Они правят только свои папки (таблица выше). Если `site` нужна функция,
   которой ещё нет, он пишет вызов по контракту, а не реализует расчёт сам.
3. **Тесты.** После завершения `api` и `site` запустить субагента `tests`: он пишет тесты на новое
   поведение и прогоняет весь набор. Код вне `tests/` он не меняет — найденные ошибки возвращает
   списком; координатор отдаёт их обратно `api` или `site` (не более двух кругов).
4. **Критика.** Когда тесты зелёные, запустить субагента `critic` на diff ветки против `main`.
   Он ничего не правит, а возвращает замечания с уровнями: 🔴 блокер / 🟡 стоит исправить / ⚪ мелочь.
   Блокеры координатор отправляет исполнителям и после исправления запускает `critic` ещё раз
   (один повторный круг).
5. **Сдача человеку.** Закоммитить, отправить ветку, открыть Pull Request. В описании PR и в ответе
   пользователю: что сделано, как проверить, итог `pytest`, оставшиеся замечания критика 🟡/⚪,
   открытые вопросы. Дальше правки вносит пользователь (или просит точечно) — по оставшимся
   замечаниям решение за ним. Сливает PR пользователь.

Мелкие правки в одном файле (опечатка, подпись, цвет) — без субагентов: сразу правка,
`pytest -q`, PR.

## Открытые вопросы методики (не решать самостоятельно)

- Точный состав портфеля 40/40/20 в НИР (сейчас 40 % MCFTR / 40 % корп. облигации / 20 % золото).
- Конвенции коэффициентов Сортино и Трейнора в табл. 4 НИР (расходятся с классическими формулами).
- Источник отчётности для мультипликаторов.
