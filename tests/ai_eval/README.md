# Оценка ассистента GigaChat

Набор вопросов к ассистенту и скрипт ручного прогона против опубликованной функции `assistant`.

- `cases.jsonl` — случаи: вопрос, «факты экрана» (формат как в `web/CONTRACT.md`) и ожидания `expect`:
  `must_refuse` (нужна оговорка/отказ), `must_mention_any` (хотя бы одна подстрока), `must_not_mention`,
  `allowed_numbers_only` (все числа ответа — из фактов или вопроса, с допуском округления; предложения со словом «условно» не сверяются).
  Префикс id — категория: `bt` бэктест, `xirr` пополнения, `sym` страница бумаги/фонда, `fr` граница и
  коэффициенты, `term` термины без фактов, `ban` запретные темы, `fab` провокации на выдумку чисел, `off` не по теме.
- `run_eval.py` — прогон и отчёт (доля пройденных, провалы с ответами). Проверка — чистая функция `check(case, response)`.

## Когда запускать

При каждом изменении `functions/assistant/prompts/system.md`, серверного фильтра вопросов или модели
(`GIGACHAT_MODEL`). Результат (доля пройденных) — в описание PR. В pytest и CI прогон не входит: нужна сеть и GigaChat.

## Как запускать

```bash
export ASSISTANT_URL=https://<id>.apigw.yandexcloud.net/api/assistant
export SITE_USER=...  SITE_PASSWORD=...     # логин сайта (Basic-авторизация шлюза)
python3 tests/ai_eval/run_eval.py           # ~59 случаев, пауза 6,5 с между запросами (лимит 10/мин)
EVAL_ONLY=ban python3 tests/ai_eval/run_eval.py   # только одна категория
EVAL_DELAY=1 ...                                  # если лимит на функции поднят
```

Код выхода 1, если есть провалы. Проверки подстроками грубые: провал читайте глазами — иногда ответ верный,
а формулировка другая; тогда поправьте `expect` в `cases.jsonl`.
